1. The cosmolike C core is agnostic to cosmology and to nonlinear prescriptions. cosmopara deliberately carries no w0, wa or n_s: the sampler (Cobaya) provides P_lin(k,z), P_nl(k,z), H(z), D(z) and chi(z) as arrays, and anything prescription-level — a fitted nonlinear formula a user may want to swap — is computed at the Python level and passed into C as arrays. Baryonic feedback already works this way and is the pattern to copy.
2. New core physics enters ONLY through a likelihood yaml key, OFF by default. With the key unset, every project and every existing run stays bitwise identical. All pybind additions are additive: no existing binding signature changes.
3. Flatness bookkeeping (deriving omega_de and similar) happens in the Python likelihood, never in C.
4. C style for any edit: // comments only, didactic in the cosmo2D.c voice; 2-space indent, never tabs; constants on the left of equality tests (1 == x); one predicate per line in guards, inline if (...) { log_fatal(...); exit(1); } (no wrapper guard helpers); one commented argument per line on every function signature; allocation through the basics.c allocators; pi-family constants through M_PI/M_1_PI/M_PI_2/M_PI_4 (never spelled-out literals, never acos(-1.0)); no binary search anywhere — uniform grids and index arithmetic; static inline, never bare inline; smallest change in existing idioms, no optional extras unasked.
- cosmolike/3pcf/physics_3pcf.c evaluates the BiHalofit matter bispectrum in C (the evaluation sits around line 2205 with its helper block; re-locate by symbol) from the supplied power tables. Its fitted coefficients need Omega_m(z)-class background inputs — exactly the cosmology dependence rule 1 forbids in C.
- The only bispectrum-shaped external input today is the baryonic feedback log response ratio ln R_B (cosmolike/3pcf/threepcf_core_bridge.h:141, the FeedbackPair input in the des_3pcf Python package). There is no supplied BASELINE bispectrum path anywhere.
- The bridge/supplied tier (threepcf_core_bridge.c, the pybind "core" submodule) already supplies power, distance, growth and source tables from Python or from the core structs.
- Units at this boundary are h-units directly: k in h/Mpc, P in (Mpc/h)^3, chi in Mpc/h. No coverH0 conversion — applying one here is wrong (verified during the bridge work; an external review confirmed the stored tables already carry these units).
- The feedback tables use sorted-triangle coordinates: for sides a <= b <= c, r = b, u = a/b, v = (c - b)/a, with axes (z, ln r, ln u, v), uniform in the stored coordinate. The baseline table should use the same parameterization.
